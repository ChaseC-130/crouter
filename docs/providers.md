# Provider adapters and limits

The app uses official local clients with their own saved authentication. It never exports account cookies, injects API keys into workers, or logs raw account responses. Claude quota reads use its saved OAuth credential in memory, solely against Anthropic’s usage endpoint; credentials are never returned to the browser or classifier. JEV or Cloudflare Clef chooses project, intent, model, and effort from validated host profiles.

| Provider            | Worker integration                                                                     | Session persistence                                            | Subscription limits                                                |
| ------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------ |
| Codex               | Official `codex exec`, read-only sandbox                                               | `thread.started` ID; resume that exact ID                      | Official `codex app-server` `account/rateLimits/read`              |
| Claude Code         | Official print-mode CLI, read tools only                                               | CLI `session_id`; `--resume`                                   | Existing host OAuth account usage, including model-specific limits |
| Grok Build          | Official `grok agent stdio` ACP, read-only sandbox and restricted tools                | ACP `session/new` ID; `session/load` when supported            | Unavailable through this adapter                                   |
| Antigravity (`agy`) | Official Google stream-JSON CLI, plan mode + macOS filesystem barrier                  | `conversation_id`; `--conversation` exact ID                   | Native metadata-only `agy -p "/usage" --output-format json`        |
| Muse Code           | Official `muse exec --json`, write/shell/web tools disabled + macOS filesystem barrier | UUID bound through `--session-id`; same ID on subsequent turns | Unavailable through this adapter                                   |

**ChatGPT means Codex** here; it is the existing Codex subscription/CLI integration, not a separate browser or cookie integration. No unofficial subscription API or cookie export is used.

## Antigravity and Muse

The adapters use accounts already saved by their host CLIs. The server does not log in on your behalf or inject provider API keys. Optional trusted executable overrides are `AGY_BIN` and `MUSE_BIN`. These two web adapters currently require **macOS and `/usr/bin/sandbox-exec`**; they refuse to run on unsupported systems. The core Codex/Claude/Grok integrations support macOS/Linux.

The additional process sandbox denies filesystem writes globally, except provider-owned authentication/session storage, a private per-run temporary directory, and necessary device descriptors. It explicitly denies project writes and rejects projects overlapping those writable locations. This protects repository files even if an injected prompt or local customization requests a write. The profile does not isolate file reads or network access; use sanitized projects and a dedicated account/container for confidentiality. Provider hooks/settings remain a separate trust boundary. No unsandboxed fallback is offered.

Antigravity's plan mode adds planning instructions and is **not itself a security write barrier**; the external process sandbox is required. Its JSON stdin protocol emits `init` and terminal `result` records. Muse uses a private regular prompt file (stdin is not a supported prompt-file path), `--disable-write`, `--disable-shell`, `--disable-web-tools`, `--no-foreign-personal-context`, `untrusted` approvals, and a disabled automatic approval judge. It disables the CLI wrapper's auto-update during workers. Muse's version-1 session envelope is parsed; child task/tool output is excluded. Temporary request files are removed after the process finishes.

See the official [Antigravity headless protocol](https://www.antigravity.google/docs/cli/headless/), [Antigravity execution modes](https://antigravity.google/docs/cli/modes), [Muse CLI documentation](https://dev.meta.ai/docs/muse-code/permissions), and [Muse session protocol](https://meta-models.github.io/muse-code-sdk/next/). Verify CLI versions/flags before upgrades; unsupported protocols fail rather than being guessed.

## Grok

The adapter uses the existing Grok Build CLI and saved account on the host. Optionally set `GROK_BIN` to its trusted executable. The adapter uses ACP's advertised `cached_token` authentication method, and fails if it is unavailable. It never chooses `xai.api_key`. It persists the returned session ID before prompting. If the installed CLI cannot load sessions, continuation fails instead of opening an unrelated thread.

The process starts with `--sandbox read-only`, `--tools Read,Grep`, `dontAsk`, explicit denials for Bash/Edit/MCP, disabled web search, no subagents, and an independent agent instead of a shared leader. The client advertises no filesystem or terminal tools and denies all ACP permission requests. See [official ACP scripting](https://docs.x.ai/build/cli/headless-scripting), [permissions](https://docs.x.ai/build/features/permissions), and [sandbox profiles](https://docs.x.ai/build/features/sandbox). Grok's current macOS child-network sandbox has documented limitations; project confidentiality still requires a dedicated account/container when stronger isolation matters. Use only trusted project and user customizations; provider-managed hooks/settings remain a separate trust boundary.

## Quota display

Open **Host & usage** for detected clients, available models and efforts, quota windows, and aggregate Codex account tokens. Reads are shared and cached for up to 60 seconds, expiring sooner at the next reported reset. Failed refreshes retain unexpired readings for at most 15 minutes with a **Stale** label. Claude, Grok and Muse `Retry-After` backoff is respected. Unknown quota stays unavailable. These reads do not run inference. Crouter does not renew or rewrite saved logins; provider-owned CLI metadata commands may perform their normal account maintenance.

Codex initializes a short-lived app-server and reads `model/list`, `account/rateLimits/read`, and `account/usage/read`. Prefer `rateLimitsByLimitId` over the legacy bucket. Percentages are consumed allowance, and reset timestamps are Unix seconds. Account token totals are reported aggregates, separate from subscription percentages or billing estimates. No transcripts or project histories are scanned.

Claude’s stream-JSON SDK initialization returns the host model catalog without a user prompt. Resolved model IDs are pinned when advertised. Quotas use `GET https://api.anthropic.com/api/oauth/usage` with `anthropic-beta: oauth-2025-04-20`. The existing OAuth access token is read from the CLI’s credential file or its default macOS Keychain item. Expired or unavailable credentials leave quota unavailable; crouter does not renew or rewrite them. It sends credentials only to the fixed official endpoint and refuses redirects. Model-specific entries in `limits` and legacy Opus/Sonnet windows are preserved. Utilization is already a percentage: a value of 1 means 1% consumed.

The Claude quota approach follows [Omarchy’s native collector](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-agent-usage-claude). Its [Codex collector](https://github.com/omacom/omarchy/blob/quattro/bin/omarchy-agent-usage-codex) likewise uses app-server limits. Omarchy also scans local session statistics; crouter uses native aggregate account data and does not load unrelated session transcripts. Other [Omarchy usage projects](https://github.com/rodrigo-sntg/omarchy-ai-usage) expose additional integrations, but no unverified allowance is fabricated here. See the official [Codex app-server interface](https://learn.chatgpt.com/docs/app-server), [Claude model configuration](https://code.claude.com/docs/en/model-config), and [Claude SDK control protocol](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/query.py).

Antigravity reads its native quota command, `agy -p "/usage" --output-format json`, in a private empty temporary directory. The bounded probe allows up to 90 seconds for cold startup and kills its process group when it completes or times out. Model discovery failure no longer hides measured quota; an empty exact model scope keeps such windows out of routing until the catalog is available. The response must identify the `usage`/`quota` command, report `SUCCESS`, and contain zero agent turns when that field is supplied. Disabled and unmeasured buckets are skipped. Remaining fractions are converted to consumed percentages, ISO `reset_time` values to Unix seconds, and `5h`/`weekly` labels to window durations in minutes. Native Gemini and third-party buckets are scoped to the verified Gemini, Claude, and GPT-OSS model IDs. Unknown quota pools or model families stay unavailable. The command was verified against the installed CLI without inference. See the official [quota command](https://antigravity.google/docs/cli/commands/usage), [statusline quota fields](https://antigravity.google/docs/cli/statusline), and [CLI changelog](https://www.antigravity.google/changelog?tab=cli).

All adapters use one normalized `UsageWindow` contract: consumed `usedPercent`, optional Unix-seconds `resetsAt`, optional `windowDurationMins`, and model scopes. Missing reset metadata is never synthesized. Grok’s session-token `usage` command is separate from subscription allowance. The quota adapter initializes ACP and reads `x.ai/billing` without opening a session or sending a prompt. If the CLI omits the method, it reads `GROK_HOME/auth.json` (default `~/.grok/auth.json`) and sends the existing unexpired subscription token only to `GET https://cli-chat-proxy.grok.com/v1/billing?format=credits`. It maps measured credit percentages and full billing-period bounds; missing percentages never become zero.

Muse reads `providers.meta.access_token` from `MUSE_AUTH_PATH` (default `$XDG_CONFIG_HOME/muse/auth.json` or `~/.config/muse/auth.json`), falling back on macOS to the CLI’s `ai.meta.dev.credentials` / `meta` Keychain item when no inline token exists. A saved `dca:` device token is required. `POST https://api.meta.ai/muse-code/key` returns the subscription’s session and weekly windows. Returned inference keys, identity and payment details are discarded. Inactive subscriptions, missing login access and missing `subs_usage` show an explicit diagnostic rather than fabricated quota. All HTTP reads refuse redirects, cap response size, respect cooldowns and retain only normalized quota in memory. These implementations follow the documented [CodexBar Grok adapter](https://github.com/steipete/CodexBar/blob/main/docs/grok.md), [Muse adapter](https://github.com/steipete/CodexBar/blob/main/docs/muse.md), and [Antigravity adapter](https://github.com/steipete/CodexBar/blob/main/docs/antigravity.md).

## Model and effort decisions

Automatic routing considers installed, supported clients and their advertised model/effort combinations. Codex and Claude catalogs come from the host; Grok and Antigravity read their native `models` command. Antigravity’s effort variants are represented by the model IDs advertised by that CLI. Muse currently offers **Host CLI default** where a verified model catalog is not exposed. A provider override narrows the catalog. The model list in **Host & usage** controls eligibility across all effort profiles and provider overrides. Usage-aware routing is off by default; when opted in, the configured reserve (20% by default) must remain in every reported applicable window. A fresh reading within two minutes is required, and stale, missing, expired, or unsupported usage does not qualify. A passed reset invalidates the cached reading until refreshed. Usage balancing compares allowance above the reserve to the fraction of each window remaining, taking the lowest headroom score across applicable windows. Missing duration/reset data uses percentages only. Shared identical pools split their weight between models without multiplying it for effort profiles. Each request samples a recommendation; the classifier uses it when capable and consistent with matching rules. Off means quota is omitted from classifier payloads and eligibility gates. The classifier cannot invent profiles, and unknown choices fail before task creation. Project/intent decisions require 0.75 confidence; the worker choice accepts the top advertised profile with a positive score, so similar suitable models can share probability without blocking a queued task. No provider fallback occurs during a worker run.

Tasks save their selected provider/model/effort in private Markdown. Codex receives `--model` and `model_reasoning_effort`; Claude receives `--model` and `--effort`, including on resume. Grok and Antigravity receive their selected `--model`; Grok’s global flag precedes the ACP agent command. Existing tasks without these fields retain their CLI defaults. Model selections, usage preferences, general instructions, and ordered model rules stay in the private `routing.json` file and apply to new tasks. Existing SQLite preferences migrate automatically. File edits and UI saves use the same configuration. Matching rules guide only the worker decision and take priority over balancing, subject to enabled models and eligibility. Models start unselected and require explicit opt-in. Legacy Gemini tasks use agy with a new session; Gemini session IDs are never resumed by agy. A decision is revalidated against current preferences before task creation. Quota and model caches stay in server memory; secrets and raw account responses are never stored as project knowledge.

## Main conversation events

Every crouter worker success/failure appends a bounded assistant event identifying its project, provider, and task. These events appear in the contiguous chat after the next refresh, even if the user is looking at another project's dashboard or the tab was closed when the task finished. Project filters affect the task dashboard, not this global display. Events remain display history and are never sent back to the routing classifier or another worker as memory.

The integration covers worker turns started by crouter. It does not scrape unrelated desktop/browser chats or assume that an externally resumed session changed task status. Interrupted server runs retain task/session state and require the recovery flow in the README.

## assistant-ui

The conversation uses [assistant-ui's MIT React primitives](https://github.com/assistant-ui/assistant-ui) and an [external-store runtime](https://www.assistant-ui.com/docs/runtimes/custom/external-store). SQLite remains the local display store; the external runtime maps current messages into UI state. New-message callbacks send only the current text to the stateless routing endpoint. No Assistant Cloud, hosted history, model gateway, telemetry integration, branching memory, or API-key backend is enabled.
